# 0.4.0 validation and limits

The change rebuilds the extension from `web-app/extension` rather than editing minified runtime scripts. The prior packaged Facebook fixes are restored from the committed maintenance patch. Instagram recipes are preserved from the shipped 0.3.1 runtime and are now checked in as an explicitly generated compatibility module.

## Coverage contract

- The default Facebook tagged view combines both tagged-post and tagged-photo/video activity sources. Source-specific views remain available.
- Each content-script call gathers at most eight scroll passes, retaining rows as they disappear through virtualization. The background saves discoveries after every chunk.
- A run pauses after twenty chunks or four chunks with no new identities. It does not impose an overall 5,000-post cap. Continue reuses the inactive worker tab and scroll position if it still exists at the expected URL.
- Closing/navigating that worker or restarting the browser can require a new traversal. Saved results remain visible; a successful new chunk replaces the source snapshot. Old tag-removal results are not inferred from that cache.
- An exact visible end notice establishes only the end of the exposed source. It does not prove every tag in the account's lifetime was accessible. Posts can be withheld, removed, filtered, or inaccessible on Facebook.
- Content without an exposed stable URL or row identifier falls back to a text/date fingerprint. Identical undated rows may not be distinguishable.
- A partial verification scan never confirms a removal merely because a post is missing.
- Paused worker tabs are retained for continuation. A fresh scan closes the previous worker only if its ID and URL match. Users may close them; a later continuation will restart traversal.
- Saved lists are separated by platform/tool/source, not by Facebook login. Clear Footprint data when switching accounts on a shared browser profile.

## Post-preview contract

Images/post links are captured from activity rows. Load post previews opens up to twelve recognized Facebook/Instagram permalinks per request in an inactive tab, reading visible caption/poster data and saving it locally. Repeat to process another batch. Authentication and security-check pages stop this process. Missing, private, deleted, or unlinked posts may have no preview. Expired media falls back to an explicit message and original link where available. No authenticated embeds, remote scripts, or platform APIs are injected into the dashboard.

## Verification

- Main app and extension TypeScript checks.
- Vitest source suite, including virtualized collection, conservative end detection, URL validation, post previews, incremental storage, source union, continuation, and failed navigation preserving cache.
- Production app and extension builds.
- Local Chromium visual and interaction checks against the production web build and extension UI with synthetic storage/API fixtures. The cloud browser could not reach the local development server; the standard Playwright Chromium download failed, so a Chromium binary from the npm-distributed @sparticuz/chromium package was used outside the repository.
- UI fixtures exercise card expansion, Keep decisions, Needs review filtering, navigation/reload persistence, inventory download, continuation requests, sample import, and search. They do not sign in to Facebook or remove real tags.

Live Facebook historical coverage, real-account tag removal, and preview availability still require testing with the user's installed extension. This change must not be described as guaranteeing all posts.

## Visual review

The generated design concept is the start-screen reference: pale lavender canvas, white surfaces, violet action color, peach sample strip, mint local-processing note, large Bricolage heading, and a two-column import/instructions layout. Desktop (including the concept-native 1505 × 1045 viewport) and mobile renders are inspected for these six properties and overflow. Existing Footprint brand icon, functional upgrade controls, platform-specific instructions, and the privacy footer on data views are intentionally retained; fictitious footer links and decorative details from the concept are omitted. The extension applies the shared tokens and adds image-led review cards. Browser screenshots use animation completion to avoid capturing entry transitions mid-frame.
